# 语音识别方案（主备切换）

> 版本：v0.1 · 2026-11-11
> 目标：主用硅基流动（免费），额度耗尽时自动切到火山引擎豆包，用户无感知。

---

## 1. 设计原则

1. **默认零成本**：正常情况走硅基流动 `SenseVoiceSmall`，免费。
2. **失败降级不打断对话**：切换时用户只会看到状态行短暂变化，不需要重新按。
3. **切换不是每个请求重试一次**：一旦判定某供应商额度耗尽，本次启动内不再尝试，避免白白等待。
4. **配置可关断**：两个供应商都能单独关掉，方便排查。

## 3. 录音文件识别 vs 一句话识别：到底差在哪

这是你问的核心问题。两者不是"新旧版本"关系，而是**两种不同的调用模型**。

| | 一句话识别 | 录音文件识别 |
|---|---|---|
| **调用模型** | 同步，一问一答 | 异步，提交任务 → 轮询/回调取结果 |
| **协议** | 自定义二进制帧（非普通 JSON） | HTTP + JSON |
| **音频来源** | 直接传音频数据 | **必须先上传到公网 URL**，服务端自己去下载 |
| **单次时长** | ≤ 60 秒 | 数小时 |
| **计费** | 按次，3.5 元/千次 | 按时长，0.8 元/小时 |
| **5 秒语音的成本** | ¥0.0035 | **¥0.0011**（便宜 3.2 倍） |
| **典型延迟** | 亚秒级 | 提交后等几秒（含排队） |
| **适合场景** | 实时对话 | 会议录音、字幕、离线转写 |

### 结论

- **便宜的是录音文件识别**（0.8 元/小时 vs 3.5 元/千次），你偏向它是对的。
- **但它的标准版/大模型版都要求传一个可公网下载的音频 URL**。手表没法提供这样的 URL——
  要么自己搭中转服务，要么换成别的形态。
- **一句话识别是同步的**，交互上更适合手表，但贵 3.2 倍。

### 折中：录音文件识别「极速版」

火山还有第三个端点，单次同步调用，**支持 base64 直传音频，不需要 URL**：

```
POST https://openspeech.bytedance.com/api/v3/auc/bigmodel/recognize/flash
```

我实测过这个端点在线上可用（错误 key 返回 `Invalid X-Api-Key`，说明路由存在）：

```
# 缺请求头时
code 45000000  error extract basicHttpRoutingPreference missing X-Api-Request-Id
# 补齐 X-Api-Request-Id / X-Api-Resource-Id 后
code 45000010  Invalid X-Api-Key
```

它在**一次请求内返回结果**，不需要 URL、不需要轮询。

### ⚠️ 价格更正（2026-11-11 复核）

之前误记为「0.8 元/小时」，**实际价格是 4.5 元/小时**。
0.8 元/小时是另一个产品「豆包录音文件识别模型 2.0」的价格。

| 产品 | 推理服务单价 | 5 秒语音 | 能否直传音频 |
|---|---|---|---|
| 豆包录音文件识别模型 2.0 | **0.8 元/小时** | ¥0.0011 | ❌ 要 URL |
| 大模型录音文件识别（标准版） | 2.3 元/小时 | ¥0.0032 | ❌ 要 URL |
| 大模型录音文件识别（闲时版） | 1.2 元/小时 | ¥0.0017 | ❌ 要 URL |
| **大模型录音文件识别（极速版）** | **4.5 元/小时** | **¥0.00625** | ✅ 支持 base64 |

**结论：便宜的不支持直传，支持直传的贵 5.6 倍。**

极速版一轮语音 ¥0.00625，是 DeepSeek 一轮对话成本（¥0.0015～0.003）的 **2～4 倍**，
不满足「语音成本必须低于 AI 成本」的要求。

**当前决策：仍用极速版作兜底。**
理由是触发条件为「硅基流动免费额度耗尽」，实际极少发生；
为中转 URL 额外维护一台服务器，成本远高于省下的几分钱。若将来兜底成为常用路径，
再补一个中转服务切到模型 2.0。

## 4. 切换判定规则

### 4.1 什么情况算「额度满了」

按优先级判定，命中任一即触发切换：

| 类别 | 判定条件 |
|---|---|
| **HTTP 状态码** | `402`（余额不足）、`403`（无权限/未实名）、`429`（限流/额度耗尽） |
| **响应体关键词** | `quota`、`insufficient`、`exceed`、`rate limit`、`额度`、`余额`、`限流` |
| **硅基流动错误码** | `30014`（token 无效）以外的鉴权类错误 → 不切换，提示用户改 key |
| **连续失败** | 同一供应商连续失败 3 次（任意原因）→ 本次启动内切换 |

**不切换的情况**：网络不可达（`Unable to resolve host`）。那是设备没网，
换供应商一样连不上，应该直接提示「手表没有网络」。

### 4.2 断路器

```
provider.state = OK | EXHAUSTED
```

- 触发切换 → `EXHAUSTED`，并写入 SharedPreferences 记下时间戳
- `EXHAUSTED` 期间所有请求直接走备用，不再尝试主供应商（避免每次都白等一轮超时）
- **恢复时机**：
  - 下次冷启动（重新打开应用）时重置为 `OK`
  - 或距离上次标记超过 **6 小时**自动重置
- 状态在状态行短暂提示：「已切到备用识别」，2 秒后恢复正常文案

### 4.3 超时

| 供应商 | 连接超时 | 读取超时 |
|---|---|---|
| 硅基流动 | 8s | 20s |
| 豆包 | 8s | 15s |

主供应商超时 → **不算**额度耗尽，但计入"连续失败 3 次"的计数器。

## 6. 实现改动

### 6.1 配置项（`Config`）

新增：

| key | 说明 |
|---|---|
| `asr_provider` | `auto`（默认）/ `siliconflow` / `volc` |
| `volc_key` | 火山新版控制台的 API Key（`X-Api-Key`） |
| `volc_resource_id` | `volc.seedasr.auc`（模型2.0）/ `volc.bigasr.auc`（模型1.0） |
| `volc_app_key` / `volc_access_key` | 旧版控制台才需要，留空走新版 |
| `asr_exhausted_at` | 断路器时间戳 |

### 6.2 代码结构

```
Api.transcribe(cfg, file)
    │
    ├─ AsrRouter.pick()  →  返回要用的供应商
    │
    ├─ SiliconFlowAsr.transcribe()   ← 现有实现，改造
    │       └─ QuotaException → 标记 EXHAUSTED → 继续下一个
    │
    └─ VolcAsr.transcribe()
            ├─ flash 端点（首选）
            └─ 一句话识别（兜底，默认关）
```

新增一个 `QuotaException`，由各供应商在识别到额度类错误时抛出，
`AsrRouter` 捕获后决定切换还是直接失败。

### 6.3 对现有代码的影响

- `Api.transcribe()` 签名不变，内部改成走 router，`MainActivity` 不用改
- 错误文案新增：「语音额度已用尽，已切换到备用通道」
